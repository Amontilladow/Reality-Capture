# Missing official files: what M4 must obtain and how each plugs in

Request from ADM SDD (gis.support@adm.abudhabi.ae), quoting spec v1.18.2 Table 1 (p.6):

| # | File | Why it is needed | Integration point | Steps when received |
|---|---|---|---|---|
| 1 | **Official ADM DWG template(s)**: Plot, Roads, Services (v1.18.2) | Exact layer names (resolves DISCREPANCIES X-02..X-05, X-11), attribute block definitions, title block name and fields, dimension style, `Track` linetype, lineweight convention | `adapters.OfficialTemplate` (`--template`, `JobSettings.template_path`); comparison is shown in every report under *Official integrations* | (1) Save each template as DXF 2010 in AutoCAD. (2) Run `m4adm prepare … --template <tpl>.dxf` and review `missing_layers`, `layer_property_differences` and `block_tag_differences`. (3) Correct `rules/adm_v1.18.2.yaml`; record each change in DISCREPANCIES and move affected rules from PENDING to VERIFIED_SPEC. (4) Next milestone: copy layer, block, linetype and dimension style definitions from the template into outputs (ezdxf `Importer`) instead of building layer records from the tables. |
| 2 | **Official QC tool `<QC Tool>.fas` (v1.18.2) and its user manual (PDF)** | The authoritative check set; error-message meanings; tolerances | `adapters.OfficialQC`, `m4adm attach-qc`, the UI *Official QC* panel | (1) Run the documented manual procedure (`adapters.MANUAL_QC_PROCEDURE`). (2) Attach the unmodified report. (3) Map each QC error message to a manifest rule id (add a `official_qc_codes` field) and calibrate tolerances. (4) Optionally automate with `accoreconsole` + `APPLOAD` on a licensed AutoCAD workstation. The `.FAS` is never decompiled or re-created. |
| 3 | **Paired drawings**: at least 3 real M4 source drawings with their ADM-accepted outputs (one each for Plot, Roads, Services) plus any ADM rejection reports | Calibrate mapping hints, tolerances and severity; build regression tests | `tests/` (a real-data suite that self-skips when files are absent, as in `tools/bim-debug`) | Store them outside git (`reference/`). Add tests asserting that the tool's findings on the accepted output include no ERROR that ADM did not raise. Build a project layer-mapping library (`layers:` YAML) from the source↔output pairs. |
| 4 | **ADM confirmation of PDF discrepancies** (DISCREPANCIES X-02..X-19, in particular X-07 date order, X-08 token case, X-09 zone 39, X-12, X-13, X-14, X-18) | Turns PENDING rules into VERIFIED_SPEC | `rules/adm_v1.18.2.yaml` | Update the manifest evidence and limitation fields, run `m4adm matrix`, and commit. |
| 5 | **CDP Project ID format** | Stricter ADM-NAME-002 | `validate.filename` | Add a regex to the manifest `filename` section. |
| 6 | **DWG conversion route decision** (AutoCAD console on an existing seat, or ODA File Converter after a licence check) | DWG output (ADM-FMT-001) | `adapters.DWGConverter` / a new `AutoCADConsole` adapter | See ARCHITECTURE §DWG strategy. |
