# Decisions

Each decision was reversible and low-risk, made under the build brief's continuous-execution rule (A3).

| # | Decision | Alternatives considered | Reason |
|---|---|---|---|
| D-001 | Build as a self-contained Python app in `apps/adm-gis-prep` inside the existing monorepo. | A separate repository; a NestJS module in `apps/api`. | The repo already hosts a Python service (`apps/ai-service`). The tool must run locally, offline and without the cloud platform, so it shares no runtime with the TypeScript apps. |
| D-002 | Stack: Python ≥3.11, ezdxf 1.4.5, shapely 2.2.0, pyproj 3.8.0, pydantic 2, FastAPI + Jinja2, pytest, all pinned (`requirements.txt`). | Using QGIS/GDAL or the AutoCAD .NET API. | All are open source with no licence cost, pip-installable on Windows engineering PCs, and need no AutoCAD. |
| D-003 | **DXF-first**: output DXF R2010 (AC1024). DWG is a documented next step (see ARCHITECTURE §DWG). | ODA Drawings SDK or RealDWG (paid); driving AutoCAD. | These are hard stop A4(e) (no paid SDK). AC1024 is the format family that AutoCAD 2010-2012 writes natively, so AutoCAD 2012 opens it. |
| D-004 | The rule manifest is YAML (`rules/adm_v1.18.2.yaml`). Appendix 2 is extracted by script into a separate generated YAML that is bound to the PDF hash. | Hand-typing the 1,218 usage rows. | The extraction is reproducible and the row count was cross-checked (1,218). A hash mismatch refuses to load. |
| D-005 | The compliance matrix is generated from the manifest (`m4adm matrix`), and a test fails if it is stale. | A hand-maintained Markdown file. | One source of truth, so the matrix cannot drift from the code. |
| D-006 | Spelling conflicts inside the PDF: the layer names follow Tables 5-7 and the Section 6 spellings are accepted as aliases, each with a warning. | Picking the Section 6 spelling. | Tables 5-7 are the layer specification. The official template must settle it (DISCREPANCIES X-02..X-05). |
| D-007 | Case-only layer-name differences are mapped automatically, with a warning. | Sending them to the review queue. | AutoCAD layer names are case-insensitive, so this is unambiguous. |
| D-008 | Entities on unrecognised layers are **never** classified. They go to the review queue and are written to the `additional` file with their original layers. Name-similarity hints are displayed only. | Heuristic classification by colour, position or geometry. | E5/G2 (no invented classifications). The additional file is allowed by spec §4.1, and it means nothing is lost. |
| D-009 | Layer-table records (colour, linetype, lineweight) of ADM layers are set to the verified values in the output automatically, and logged. Entity overrides are only *proposed* (BYLAYER fix). | Auto-fixing entity overrides as well. | The layer table is not engineering geometry, and the values are VERIFIED_SPEC. Entity changes need acceptance (D7.2). |
| D-010 | "Default (0.25)" lineweight is stored as AutoCAD *Default* (-3). 0.30 and 0.40 are stored as 30 and 40. | Storing 25. | Follows the wording of the table. To be confirmed against the template. |
| D-011 | Geometry fixes are opt-in by id or by `all:KIND`: CLOSE_FLAG, TO_LWPOLYLINE (lossless), DENSIFY_BULGES (deviation ≤ `arc_sagitta`, default 0.01 m), BYLAYER. | Automatic repair. | D7.2 and A4(b). Every application is logged with its before/after state and maximum shape change. |
| D-012 | Densification is exact: points are placed on the true arc at equal angular steps and the original vertices are kept. | ezdxf's Bézier path flattening. | It gives exact deviation control and consistent spacing (spec Figure 2). |
| D-013 | No deletion fixes are offered, including for zero-length or duplicate items. | "Delete duplicate" as a fix. | No silent deletion (G2). Engineers delete in CAD after deciding which copy carries the attributes. |
| D-014 | A CRS declaration never moves geometry. A transformation runs only with an explicit target or PROJ pipeline **and** both confirmations, and only on point-wise-safe entities (straight LWPOLYLINE, POINT, unrotated INSERT). Anything else blocks it. | Transforming everything pyproj can handle. | D1. Arcs, rotated blocks and OCS entities would need more than a point-wise transformation to stay correct. |
| D-015 | The extent plausibility window (lon 51.0-56.5, lat 22.4-25.5) is an ENGINEERING_CHECK that only produces warnings. | None. | It catches arbitrary/local coordinates (spec §4.4) without ever acting on them. |
| D-016 | The units header ($INSUNITS = metres) is written to the output only when the engineer confirms metres. $LUNITS is set to Decimal automatically. | Always setting the header. | Without confirmation, setting metres would be a false claim. $LUNITS is display-only. |
| D-017 | Shared layers (Title, DimensionLine) are copied into each selected dataset file, with an ENG-SHARED-001 warning for review. | Asking before every run. | Copying preserves the information. Per-entity handle mapping lets the engineer change it. |
| D-018 | Unused block definitions are omitted from the prepared output (logged by name). Unused linetypes are reported only. | Purging nothing. | Spec §5 rule 7. Splitting into dataset files creates new unused blocks, so purging per output is necessary. Arrow blocks referenced by dimension styles count as used. |
| D-019 | The job lifecycle is `<id>.partial` → atomic rename to `<id>`, or `<id>.failed` with error.json. Each file is written with temp + `os.replace`. | Writing in place. | E6: a failed run can never look successful. |
| D-020 | Jobs are immutable. Review decisions create a new job (`parent_job`) from the unchanged original. | Editing a job in place. | Full traceability between runs. |
| D-021 | Always-present notes about producing DXF instead of DWG are INFO, not WARNING. The limitation is still shown in every report and banner. | WARNING. | As WARNING, "Ready for review" could never be reached, which would hide useful status. |
| D-022 | An official QC status (passed/failed) is shown only when the engineer attaches the official tool's output file. The file is archived unchanged with its SHA-256 and attestation. | Never showing a QC status. | F2: the status must be backed by real output. The `.FAS` is not emulated (E7). |
| D-023 | The UI binds to 127.0.0.1 only, with no API docs endpoints, server-rendered pages and no external assets. | Exposing the UI on the network. | G4: drawings stay local. It also works offline. |
| D-024 | The ADM PDF is not committed (`reference/*.pdf` is git-ignored). It is identified by SHA-256 in the manifest. | Committing the PDF. | It is an ADM-controlled document distributed to clients. Traceability is kept through the hash. |
| D-025 | Synthetic fixtures carry a `SYNTHETIC` header property and `SYNTHETIC_` file names. Their blocks are built from the PDF tables. | Committing no fixtures. | Required by H2. They are clearly marked as not the official template. |
