# Discrepancies: DRM BDMS 4.1 profile

These are differences between the BDMS 4.1 specification text (SPEC), the QC tool user manual (QCM) and the four drawings ADM accepted after official QC (SAMPLES). Where the SPEC text and the accepted SAMPLES disagree, the tool follows the SAMPLES: they show what the official QC actually accepts. Each item is still open for DRM confirmation (tpd.gis@drm.gov.ae).

| ID | Topic | SPEC / QCM says | SAMPLES show | What the tool does |
|---|---|---|---|---|
| B-01 | Units | SPEC §1.4.2 (p.14): 1 drawing unit = **1 cm**. | Coordinates are UTM 40N **metres** (E≈257,700, N≈2,704,600). The building measures 63.6 m. `$INSUNITS = 4` (mm). | Metres are required: the engineer confirms them and UTM plausibility is checked. `$INSUNITS` is not enforced. |
| B-02 | Lineweight | Table 1: "Default (0.25)". | Every layer has an explicit 0.25 mm (value 25). | Both are accepted. An accepted value is never rewritten. |
| B-03 | Empty layers | QCM 4.1 #8: "Mandatory Polygon is missing … while the Layer exists". | F3 and G have no Window/WindowDetail layers at all. | Empty specified layers are left out of the prepared file. |
| B-04 | Layer table | Table 1 numbering skips rows 7, 8 and 11 (old BuildingOther layers). `0`/`Defpoints` are not listed. | `0` and `Defpoints` are present in every sample. | Allows `0`/`Defpoints`. Removes every other unspecified layer from the output. |
| B-05 | BuildingRoofDetail | Listed as a layer (Table 1) but its block is **not described** in §1.4.6.1. | The block has tags `BUILDINGNUMBER`, `BUILDINGHEIGHT`. | The block structure is taken from the template blocks in the SAMPLES. Mandatory status is pending. |
| B-06 | Date format | SPEC example `01-Jan-2000` (mixed case). | `14-JAN-2026` (upper case). | Both are accepted; the case is not enforced. |
| B-07 | Snapping | QCM 4.5: "Where layers intersect vertices must exist in both geometries", tolerance 0.0000. | Accepted drawings contain edge **crossings** without vertices and 0.9–4 mm near-miss vertices. They contain **no** T-junctions (a vertex on another layer's edge without a vertex there). | T-junction = ERROR (official snapping error). Crossings and near misses = WARNING (DRM-SPEC-TOPO; spec rule 1). Both block in strict mode. |
| B-08 | Space ↔ Unit | QCM 4.4 #15 "Space not exist in a Unit found with a UnitNumber". | A space overhangs its unit by ~0.35 m and was accepted. | A space belongs to the unit holding most of its area. The overhang is reported separately (DRM-LOG-21, WARNING). |
| B-09 | Door/Window ↔ Space | QCM 4.4 #24-25 "Window/Door exits without corresponding Space polygon". | 3 windows (F1) and 1 door (G) touch no space and were accepted. | The SpaceNumber reference is an ERROR (DRM-ATT-15). Geometric contact is a WARNING (DRM-LOG-21). |
| B-10 | Code lists | SPEC: UnitType = UPC Level 1 only, UsageType = UPC. QCM Appendix 1 prints its own lists (with typos "Inrastructure", "Employee Hosing"). Part of the UnitUsageType list is images. | `UsageCategoryType = Residential`, `UsageType = Household Living`, `UnitType = Residential`, `UnitUsageType = Household Living`. | QCM lists are used exactly as printed. UnitUsageType is checked against the UPC + manual union (376 terms) as a WARNING. |
| B-11 | Text on Title | SPEC rule 11: title, border and text go on Title or Miscellaneous. QCM example report shows "Invalid geometry found – Title 69". | Title holds 1 closed polyline + 2 blocks only. | TEXT/MTEXT is allowed on Title/Miscellaneous. LINE, HATCH etc. are errors everywhere. |
| B-12 | Format | SPEC §1.4.1: AutoCAD **2006 or later**. | SAMPLES are AutoCAD 2018 (AC1032). | No upper release limit for BDMS. Output is R2010 DXF. |
| B-13 | Coordinate zone | SPEC §1.2: zone 39 **or** 40 "based on the location of the Building". | Zone 40. | Target EPSG:32639 or EPSG:32640, chosen by the engineer. |
| B-14 | Zone/Sector lists | QCM 4.1 #4-5: checked against lists "pre-listed in the tool script". | – | Not available (compiled into the .FAS). Only consistency between the file name and the blocks is checked (DRM-GEN-04 NOT_IMPLEMENTED). |
| B-15 | Unit numbering | SPEC 1.4.6.1.8 #2: "Unit Number should be unique in the entire building". | One unit per floor, all numbered `1`. | Uniqueness is checked per floor file. Unit `1` repeated on every floor is accepted in the SAMPLES, so cross-floor uniqueness is not enforced. |
| B-16 | Space numbering | SPEC "Spaces ID Code": unique positive integers per floor, numbering scheme left to the constructor. Official QC report key note 8: "UnitNumber, SpaceNumber, BuildingNumber ... are progressive numbers starting from number 1, 2, 3". | `KHALIFA CITY-SE45_01-C8-1-G` skips 5, 20 and 22 and passed official QC with 0 errors. | Unique positive integers = ERROR. Gaps = DRM-ATT-51 notification (INFO) only. The converter still numbers spaces 1..n. |
| B-17 | SpaceNumber data entry (SpaceDetail) | Trial 01 row 10: 9 SpaceDetail blocks with "Incorrect SpaceNumber data entry". | 12 blocks. 2 have an empty SpaceNumber (reported as polygons without block). The other 10 have a number but an empty FloorNumber/UnitNumber. | DRM-ATT-49 flags the 10. Why ADM flagged 9, not 10, is unknown. **No rule was tuned to hit 9.** A single "correctly entered" space would also explain 2 doors being accepted (see B-18), but one report cannot identify it. **Explained by trial 02:** the official QC reads block attributes by position, and the accepted drawings store them in reverse spec order (SPACEUSAGE, FLOORNUMBER, UNITNUMBER, SPACENUMBER). Our draft wrote spec order, so ADM read SpaceUsage as SpaceNumber: 9 = the 12 spaces minus the 3 with an empty SpaceUsage. Fixed by writing the template order (DRM-ATT-52). |
| B-18 | Door/Window ↔ Space link | QCM 4.2 #15-16, #24-25: "SpaceNumber ... correspond to the correct SpaceNumber in the drawing". It does not say UnitNumber/FloorNumber are part of the match. | Trial 01: all 34 windows reference SpaceNumber 11, which exists, with UnitNumber/FloorNumber empty on both sides, and all 34 were rejected. 15 of 17 doors were rejected. Geometrically every door and window touches the space it references. A SpaceNumber-only lookup would reject none. | Match on (SpaceNumber, UnitNumber, FloorNumber), and an empty part never matches (DRM-ATT-15). This reproduces windows exactly (34). It gives 17 doors where ADM gave 15; the 2 accepted doors are unexplained. The hypothesis is **partly confirmed**: empty identifiers break the link, but the exact matching rule is not proven. |
| B-19 | BuildingRoof | DRM-LOG-03 lists BuildingRoof among the required polygons (QCM 4.4). | Trial 01 has no BuildingRoof and the official QC did not report it. **Resolved by trial 02:** once the file name was valid, ADM reported "Floor exits without corresponding BuildingRoof Polygon" (and "BuildingOutline exits without corresponding Plot Polygon"); the file-name error had hidden these checks. Every accepted floor file repeats the BuildingOutline as its BuildingRoof. | Missing BuildingRoof = ERROR again, under the official wording. The converter writes the BuildingRoof on the building outline (as the accepted drawings do), with BuildingHeight from settings. |
| B-20 | Missing values in Space/Door/Window/Title blocks | QCM 4.2 #3: missing mandatory values are counted per attribute block. | Trial 01: empty FloorNumber on all 63 Space/Door/Window blocks, empty Spaceusage on 3 spaces and empty title blocks produced no "Missing Value" row. Only BuildingDetail (1) and FloorDetail (1) were listed. | Detailed DRM-ATT-03 findings stay (they are real omissions). The official-terms summary counts one per block, lists Building/Floor/Unit/Plot/Roof blocks under the official row, shows Title under a separate labelled row, and leaves Space/Door/Window out (ADM reports them as data-entry/link errors). |
| B-21 | Attribute order inside Detail blocks | The spec tables list attributes in one order; the tag names identify them. | The official QC reads attributes by position. All DRM-accepted KHALIFA CITY drawings store them in reverse spec order (ProjectDetail excepted). Trial 02: a draft in spec order got "Inconsistent Building Number" (x2), "Incorrect FloorHeight data entry" and SpaceNumber data-entry rows although the values were right. | `template_order` per block in the manifest, taken from the accepted drawings; the converter and the synthetic fixtures write it; new DRM-ATT-52 flags a drawing whose blocks use another order. |
